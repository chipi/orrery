# ADR-097 — No staging tier: releases go straight to prod, GitHub Pages serves only the docs

> Status · Accepted · 2026-11-10 (operator) · supersedes the staging parts of **ADR-014** (GitHub Pages as preview environment), **ADR-070** / **ADR-071** (the app+docs publisher chained off docker-e2e), **ADR-082** (the dev → staging → prod ladder) and **ADR-083** (the mobile staging↔prod switcher)

## Context

Since July 2026 the app had three tiers: dev, staging (the app bundle on GitHub Pages at
`chipi.github.io/orrery`, published by `staging.yml` after every green docker-e2e, smoked by
`validate-staging.yml`) and prod (the self-hosted VPS, `deploy-prod.yml`, manual).

Staging stopped earning its cost:

- Pages is a different host from prod: no nginx headers or CSP, a `/orrery/` base path, no `/data`
  overlay. The staging smoke skipped the checks that matter for prod and could pass while prod broke.
- The app copy on Pages was a divergent, SEO-duplicate mirror (RFC-035, ADR-096 noindex) and a
  ~2.5 GB bundle on the `gh-pages` branch.
- Two telemetry rungs, two GitHub environments and a mobile switcher existed only to feed it.
- Every release already needed `validate-prod` on the real host, so staging was a second, weaker
  validation in front of the first.

## Decision

1. **There is no staging tier.** The release flow is: merge to `main` →
   `gh workflow run "Deploy to prod VPS (orrery)" --ref main` → validate-prod (the deploy's own
   `validate` job, then `validate-prod.yml` on its completion and daily). The deploy stays manual;
   dispatch it only for a commit whose `ci.yml` and docker-e2e runs are green.
2. **GitHub Pages serves only the project docs.** `deploy-docs.yml` (CI-gated, ADR-070) publishes
   the whole `gh-pages` tree: a static root page forwarding to `https://www.orrerylearn.com/`
   (`docs/.vitepress/gh-pages-root/index.html`) plus the VitePress build under `docs/`, so
   `/orrery/docs/` URLs keep working. It no longer relies on `keep_files` to preserve an app bundle.
3. **`staging.yml` ("Deploy preview") and `validate-staging.yml` are deleted.**
4. **The app drops the staging tier.** `src/lib/target-env.ts`, its test, `TargetEnvSwitcher.svelte`
   and the `__MOBILE_INTERNAL__` define are removed; `sentry.ts`, `analytics.ts` and `asset-url.ts`
   read the env ladder (dev, prod) and `STREAM_ORIGIN` directly. `STREAM_ORIGIN` defaults to
   `https://www.orrerylearn.com`.
5. **Telemetry is two rungs** (prod, dev). The staging GlitchTip project (6) and Umami site
   (`6e7ddfce…`) receive nothing new.

## Consequences

- A bad commit is found on prod, not before it. The mitigations are the green-CI rule in the flow,
  `validate-prod` right after the deploy, and the rollback in `docs/ops/deploy-prod-vps.md`.
- The first `deploy-docs.yml` run after this change replaces the `gh-pages` tree, which removes the
  app bundle from the branch tip. The history keeps the blobs; shrinking the branch is a separate,
  operator-approved step.
- Mobile builds stream pruned assets from the prod origin by default.
- `scripts/validate-prod.mjs` keeps an unused `VALIDATE_TIER` knob.

## Not covered

- Deleting the staging GlitchTip project, the Umami site and the `staging` GitHub environment.
- Rewriting ADR history: ADR-014, 067, 070, 071, 082 and 083 carry a "superseded" note and are
  otherwise unchanged.
