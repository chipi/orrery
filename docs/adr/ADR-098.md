# ADR-098 — Per-locale UI message catalogues

> Status · Accepted · 2026-11-27 · operator go on the direction ("sounds like a good idea and well
> aligned with how the rest of things work"); implemented on `tech-debt/0.9.12`
> (`scripts/i18n-split-plugin.mjs`, `src/lib/i18n-split/registry.ts`, `src/routes/+layout.ts`)

## Context

The UI strings (`messages/<locale>.json`, 3,817 keys) compile with Paraglide 2.21 in its default
`message-modules` output: one module per message, and each module holds the message in **all 14
locales** behind a runtime `if (locale === …)` chain. Tree-shaking keeps only the messages a route
uses, but every kept message carries 14 languages. A visitor reads one.

Measured 2026-11-27 (`SENTRY_SOURCEMAPS=1 npx vite build`, brotli, the minified bytes of each chunk
attributed to its source modules through the sourcemaps):

| Static JS | total KB | paraglide messages KB | share |
| --- | ---: | ---: | ---: |
| shell (root layout + entry) | 189 | 41 | 22 % |
| /explore | 559 | 260 | 46 % |
| /moon | 448 | 165 | 37 % |
| /fly | 458 | 135 | 29 % |
| /missions | 139 | 85 | 61 % |
| /fleet | 108 | 50 | 46 % |

One locale's whole catalogue is 84 KB (en-US) to 97 KB (de) brotli as JSON.

Everything else the client reads per locale is already split: the content overlays are per-locale
and per-chunk bundles fetched at runtime (`scripts/build-i18n-bundles.mjs`,
`src/lib/data/i18n-chunks.js`), the Lab's message tables are one dynamic import per locale
(`src/lib/lab/t.ts`), the glossary is one file per locale. An audit for other all-locale payloads
found one small one: `src/lib/name-origins.js` (15 KB raw, the launches pages).

What was tried or ruled out:

- **`experimentalMiddlewareLocaleSplitting`** (tried before, notes in `vite.config.ts`): works only
  without client-side routing; SvelteKit navigations failed with
  `globalThis.__paraglide.ssr.<key> is not a function`.
- **`experimentalStaticLocale`** (measured 2026-11-27): set to `"en-US"`, the route sizes did not
  move. The message modules read the locale from an imported binding, which the minifier does not
  fold, so all 14 branches stay. Paraglide's intended use is one full build per locale with the
  server picking the build: 14 builds and a different deploy.
- **`outputStructure: 'locale-modules'`**: one module per locale, statically imported; Paraglide's
  own docs say it tree-shakes worse.

## Decision

Keep Paraglide as the compiler and the `m.<key>()` call sites as they are. In the client build a
Vite plugin (`scripts/i18n-split-plugin.mjs`) splits its output into **per-locale modules loaded
before the page renders**, the way the content overlays already work:

1. **Stubs.** Each message module becomes a stub with the same name that calls `msg()`
   (`src/lib/i18n-split/registry.ts`). Tree-shaking per route still applies; a stub is a few bytes.
2. **Modules.** Per locale, the plugin emits one module with the messages of every chunk all pages
   load (the entries, the root layout and the error page, with their lazy imports) and one per route
   with the messages of the chunks that route adds (its node's static and lazy closure). They are
   named by content hash (`_app/immutable/i18n/<locale>/<hash>.js`), so an unchanged catalogue stays
   cached across deploys, and a page needs two requests at most.
3. **Map.** Per locale, `_app/immutable/i18n/<locale>/routes.<version>.json` gives `root` and
   route id → module.
4. **Loading.** The root `+layout.ts` load awaits `loadMessagesFor(route.id)`; it reads `route`, so it
   runs again on every navigation, and the page renders only once its messages are in.
5. **Dev, SSR, prerender and tests** keep Paraglide's own modules (the Paraglide Vite plugin writes
   per-locale modules in dev and per-message modules in production builds); the registry is a no-op
   there. The prerendered HTML is unchanged.
   **The app build (`MOBILE=1`) is off too:** its JS is on the device, and its non-default locales
   stream from `STREAM_ORIGIN`, the web build, which does not hold the app build's hashed modules.
   It keeps Paraglide's all-locale modules (79.1 MB against the 80 MB app budget, 2026-11-26;
   with the split it was 81.2 MB), and `check-route-budget` skips it.
6. **Guard.** A stub whose message is not loaded logs `i18n-split: message "<key>" … is not loaded`
   and returns the key; the e2e and a probe across 19 routes × 3 locales found none.
7. **Budget.** `check-route-budget` counts the shared module in the shell and a route's own module in
   the route, at the largest locale.

The first design grouped messages into area chunks by usage; Rolldown's chunking put most messages
in chunks every page loads, so the split by route is simpler and gives the same bytes.
`name-origins.js` (15 KB raw, launches pages) is left for a later pass.

## Consequences

Positive:

- Each route ships its messages in one language instead of 14. Measured (brotli, SENTRY_SOURCEMAPS=1,
  messages included at the largest locale): /explore 571 → 316 KB, /fly 467 → 340, /moon 452 → 298,
  /missions 141 → 66, /fleet 112 → 70, / 63 → 12; the shell 194 → 215 (it now carries the shared
  messages, 58 KB at hi). A first visit to any page is lighter, and every later page much lighter.
- The same pattern as the content overlays and the Lab tables: one way to load translated text.
- Route budgets can come down by those amounts, which removes the pressure that pushed 3D modules
  into lazy chunks.

Negative:

- A generated layer between Paraglide and the app: a compile step, a stub module and a route →
  chunk table to keep in step with Paraglide upgrades (pinned; the step's tests cover the output
  shape it relies on).
- Navigation waits for the next route's catalogue chunk if it is not cached (one small request; the
  route's own JS chunks already load the same way).
- The shell is 21 KB heavier: the shared messages load on every first visit.

Neutral:

- Call sites, the message JSON files, the translation workflow and the term tools do not change.

## Alternatives considered

- **One whole catalogue per locale** (84–97 KB) loaded by the root layout: simplest, but every first
  visit pays the whole catalogue; small pages get heavier than today.
- **Fourteen builds** (`experimentalStaticLocale`): the ideal bytes, 14× the build time and a
  per-locale deploy.
- **Leave it**: the routes keep carrying 13 unused languages, and new UI keeps growing them 14×.
