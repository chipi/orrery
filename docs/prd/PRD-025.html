PRD-025 · Finalize the forward roadmap — comprehensive per-agency coverage through ~2035 ​

Status · Draft (re-scoped for v0.8) · re-analyzed 2026-07-11 Date · 2026-06-09, re-scoped 2026-07-11 Owner · Marko Closes into · GH epic (v0.8 content track) + per-agency slice PRs · tracking issue #313 Builds on · PRD-004 (Mission Library) · PRD-012 (Spaceflight Fleet) · backlog docs/research/forward-roadmap-2026-07-11.md (comprehensive refresh; supersedes the 2026-06-09 backlog, which is kept for history)

What changed on 2026-07-11 (the re-scope). The original PRD-025 locked a minimum representative cut — 24 missions + ~37 fleet out of ~100 candidates, "≥1 flagship per agency," with ~75 entries explicitly deferred to "v0.9+". Marko's direction: that's the wrong frame — finalize each major agency's forward roadmap comprehensively. Cover China's full Moon program, all of Russia's plans including their own station (ROS), all of ESA's and JAXA's roadmaps, ISRO, and the private sector — not one flagship each. This revision reframes the scope from "representative sample" to per-agency completeness, refreshes every entry against current (2026-07) data, and defines a tiered finalization scope so the cut line is an explicit decision, not a silent deferral.

Why this is a PRD. Which forward-looking programs and missions Orrery commits to modeling — comprehensively, across every major agency, through ~2035 — is a product-scope decision that gates months of content authoring: mission + fleet JSON, images, 3D scenes, and editorial across 14 locales. Locking the complete set with an explicit, tiered cut line — rather than a silent deferral of everything past one flagship per agency — has to happen before any new entry lands. That scope commitment is why this is a PRD and not a backlog note.

Why ​

As of today orrery's static/data/missions/ + static/data/fleet/ contain only 7 forward-looking missions and 5 forward-looking fleet entries against a world that has reset hard: NASA cancelled Gateway and announced a Moon-then-Mars surface-base architecture ("Ignition", 24 Mar 2026); China merged its crewed-lunar + Chang'e programs and recovered an orbital booster; Russia re-architected ROS around recycled ISS modules; ESA lost its US MSR partner and is debating sovereign crew; ISRO, UAE, Korea, and Brazil are standing up flagship programs and first launches. Orrery's "what's planned next" surface is a rounding error against reality. This PRD locks the complete forward content set for v0.8 so slices can execute cleanly.

Scope model — per-agency completeness, tiered ​

Coverage principle: for each major program, represent its committed forward roadmap in full — every announced-and-funded element, every in-development flagship, and the program-defining vehicles behind them — rather than a single flagship. Curation still applies at the proposed edge (we don't model every paper concept), and images/3D remain deferred (content ships with credit first, imagery catches up).

Three tiers, so the cut line is explicit:

TierDefinitionRough new-entry count (missions + fleet, after de-duping the 12 already in data)
T1 — CommittedA (announced + funded, hardware/schedule) + the architecture-reset updates to existing entries. The forward roadmap that is actually happening.~55–70
T2 — In-development depthD (active development) across every program — CLPS deliveries, all ESA science, Luna 26-29, commercial LEO stations, commercial launcher debut wave, megaconstellations. Completes per-agency coverage.~60–80
T3 — Proposed tailP (study/paper) for the biggest programs only — Neptune orbiter, Venus atmosphere SR, Interstellar Express, Yenisei/Don, Korona, HWO, Enceladus Orbilander, Mangalyaan-2. Selective, not exhaustive.~30–45

Finalization scope (LOCKED 2026-07-11) = T1 + T2 + T3 — everything. Marko's call: cover every A/D/P element across all agencies + private sector, including the proposed tail for the big programs. ~180+ new entries. Full per-item backlog with confidence + → orrery entry type mapping: docs/research/forward-roadmap-2026-07-11.md.

Every new entry is authored under a program (see PRD-029). The forward-roadmap work is the first consumer of the programs grouping layer — author the program (Artemis, Project 921, ILRS, ROS, Gaganyaan, BAS, CLPS, Commercial LEO Destinations, …) then tag its member missions + fleet. Programs are also the coverage lens: a program with a gap in its numbered sequence flags a hole to backfill.

Effort — be honest ​

Per the mission/fleet runbooks each entry is ~8 touchpoints: base JSON + index + en-US overlay + all-14-locale overlays (now core content, not deferrable) + ≥3 sourced links + fleet↔mission symmetry + (deferred) imagery. Realistic per-entry authoring is ~30–90 min for fleet, ~45–120 min for missions, plus validate-data iteration.

  • T1 + T2 ≈ 135–150 entries. That is not a one-sitting job — it's ~9 program-family slice PRs, on the order of 1–2 focused days per slice (editorial care on credit/links + the 14-locale pipeline pass dominate). Call it a multi-week content track, sequenced under Marko's supervision, one slice at a time.
  • T3 adds ~30–45 more; land opportunistically, don't gate the release on it.
  • Imagery is a separate wave (Image Pipeline v2) after content; entries ship with credit placeholders, never blocked on images.

Done definition ​

  • New entries as JSON under static/data/missions/{body}/{id}.json + static/data/fleet/{category}/{id}.json + both index.json.
  • Every entry: id, name, agency, country, status, first_flight (null if unflown), best_known_for, sourced credit, ≥3 links, fleet_refs/linked_missions symmetry.

  • npm run validate-data + npm run preflight green.

v0.8 release acceptance bar (per-agency completeness) ​

  • T1 + T2 landed across Slices 0–9 (T3 optional).
  • Per-agency coverage is complete for {NASA, US-commercial, CNSA, Roscosmos, ESA, JAXA, ISRO} — i.e. no A/D program element from the backlog missing without an explicit note.
  • surface-base + ground-observatory filter chips live on /fleet.
  • Both backlog docs retained; this PRD moves Draft → Accepted (v0.8).

Decisions (LOCKED 2026-07-11) ​

  1. Cut line: everything (T1+T2+T3), ~180+ entries. No silent deferrals.
  2. P (proposed) policy: include proposed entries (Neptune orbiter, Venera-D, Yenisei, Mangalyaan-2, HWO, Interstellar Express, Enceladus Orbilander, …).
  3. Slice order (priority agencies first): NASA → China → Russia → ESA → JAXA → ISRO → newcomers/commercial → NASA planetary/CLPS → proposed tail. See the re-ordered slice plan above.
  4. Programs paradigm: adopt the program grouping layer (PRD-029) for all new entries, and retrofit historical missions/fleet.

Risks ​

  • Date drift — most NET 20xx dates move; re-check per slice, flag >6-month slips in credit.
  • Thin newcomer sourcing — Vikram-1, VLM-1, KSLV-III, MBR lander, Turkish/African firsts lean on agency PRs + trade press; same editorial bar, source in native language + machine translation where needed (per project memory on global representation).
  • Re-resets — NASA's Ignition reset won't be the last; a mid-slice pivot edits in-flight, not deferred.
  • surface-base ↔ station and ILRS-as-program ambiguity — name/describe ILRS + Moon Base as programs, not as a single finished object.
  • 14-locale load — i18n is now core content; the translate-pipeline pass is real per-entry cost, not a footnote.
