# UX records (UXR)

Dated records of what happened in the UX work: an operator feedback list, a review run, its
findings, a plan of action, a decision session. Each is written once; a later event gets a new
record. Where they sit among the UX documents:
[UXS-000](../UXS-000-orrery-ux-architecture.md).

## Rules

- **One event, one record**, numbered in order and dated in the filename:
  `UXR-NNN-YYYY-MM-DD-<slug>.md`.
- **A record is not rewritten.** If the operator changes a point later, the change is a new record or
  a UXD; the original stays as the input it was.
- **A record does not decide.** Decisions are [UXDs](../decisions/README.md). A record lists what was
  said, by whom, and which points it contains; the UXDs and the
  [change inventory](../CHANGE-INVENTORY.md) say what happens to them.
- **Large lists are referenced, not copied.** The full numbered list stays in its working document
  (named by path in the record); the record summarises by area with the point ids.
- **No private or operational content.** Only the UX content and who said it.
