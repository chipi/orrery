# Tech-debt Phase 5 — what users download

Branch `tech-debt/phases` (never merged to main from this arc). Runs after the
i18n phase ([2026-10-30-i18n-phase-plan.md](2026-10-30-i18n-phase-plan.md)).
Sizes below are static client JS per route node (the node's import closure from
`.svelte-kit/output/client/.vite/manifest.json`), raw / brotli q11.

## 1. The 3 MB messages chunk — done

Cause: three places looked messages up by a computed key on the paraglide
module (`science_tab_<tab>` in three /science files, `galaxy_name_<id>` in
`galaxy-label.ts`, `t(key)` in `lab/t.ts`). Indexing the module makes the
bundler keep every message, so one ~3 MB chunk loaded on /science, /explore and
/lab.

Fix: explicit tables of message functions — `src/lib/science-tab-label.ts`
(typed `Record<ScienceTabId, …>`, so a new tab without a message fails
typecheck), the galaxy table in `galaxy-label.ts`, and
`src/lib/lab/lab-messages.ts` (1,099 `lab_*` messages, generated by
`scripts/i18n-tools/gen-lab-messages.mjs`).

Guards: `scripts/i18n-tools/no-dynamic-messages.test.ts` (no computed lookup or
re-typing of the messages module anywhere in `src/`); the lab parity test now
resolves keys against the lab table, fails when the table is stale, and fails
when a non-`lab.` key reaches `t()`.

Found on the way: the `planets` tab had no `science_tab_planets` message and
showed English "Planets" in every locale. Added in all 14, upper-cased like
the other tab labels, using the word the site already uses
(`credits_category_planet`).

| Route | Before | After |
| --- | --- | --- |
| /science/[tab] | + catalogue chunk ¹ | 152 KB / 50 KB br |
| /explore | + catalogue chunk ¹ | 2,127 KB / 558 KB br |
| /lab | 5,689 KB / 1,544 KB br | 2,868 KB / 756 KB br |

¹ The catalogue chunk was 3,078 KB / 763 KB br; the route totals before the
fix were not measured.

What is left in /lab (a 2,354 KB chunk) is the Lab's own 1,099 messages:
Paraglide 2.21 compiles every message with all 14 locales inline. It has no
option that ships one locale to a static (prerendered) site —
`experimentalMiddlewareLocaleSplitting` needs a server middleware. Not worked
around here; decide with item 3.

## 2. Root-layout chunk (693 KB raw / 102 KB br, every route) — done

It was the en-US image alt-text map (4,237 entries), statically imported by
`$lib/image-alt`, which the root layout imports. The only readers,
PlaceHero (/earth museum and observatory cards) and SiteStoryPanel, render on
the client only, so the static import bought no prerendered alt text.

Fix: `getImageAlt` fetches the en-US map and the active locale's map on its
first call, into a `SvelteMap` so an alt that was empty while its map loaded
re-renders. The root layout no longer fetches the locale map on every page
(a non-English visitor downloaded 0.8–1.5 MB of alt text on every load).

- JS every page loads (root node + entry closure): 1,115 KB / 224 KB br →
  422 KB / 122 KB br. No chunk contains the map any more.
- Browser check on the build: `/de/earth?museum=nasm-washington` fetches
  `en-US.json` + `de.json` and the hero alt is the German caption;
  `/missions` fetches no alt map. Mutation: with a plain `Map` instead of
  `SvelteMap` the alt stays empty (museums.spec.ts asserts a non-empty alt).
- Mobile: en-US alt text stays on device (only non-default locales are
  pruned), so the app keeps it offline.
- Not covered: a web visitor who goes offline before any page needed alt
  text has none offline until one online load (the `/data/*.json` runtime
  cache stores it on first use, as it already did for the other locales).

## 3. Per-locale i18n bundle split (3.4–4.4 MB per locale) — done

The first localized lookup on any page fetched the whole locale bundle (de
587 KB br / 2.2 MB raw, hi 613 KB br / 4.4 MB raw) and parsed it. Five trees
hold most of it (hi, br): science 199 KB, programs 110, essays 85, fleet 77,
missions 75; everything else ~70.

Fix: `build-i18n-bundles.mjs` also writes `<loc>.<chunk>.json` for chunks
science, programs, essays, fleet, missions and core (the rest), mapped by
`src/lib/data/i18n-chunks.js`, which the loader in `core.ts` shares. `get()`
fetches only the chunk a key lives in; the missions linkifier loads fleet +
missions. The whole `<loc>.json` is still emitted: released mobile app
versions stream it from the web origin.

Browser check on the build (files fetched, brotli):

| Page | Fetched | br |
| --- | --- | --- |
| /de/missions?id=apollo11 | de.missions + de.core | ~188 KB |
| /de/fleet?id=saturn-v | de.fleet + de.core | ~188 KB |
| /de/science/orbits | de.science | ~189 KB |
| /de/mars | de.core | ~116 KB |

Before: de.json, 587 KB br, on each of them.

Mobile: the app keeps the en-US chunks on device and prunes the unused whole
`en-US.json`; the service-worker precache lists `en-US.*.json`.
`npm run build:mobile` passes its size budget (70.5 MB / 77 MB) and
`playwright.mobile.config.ts` passes 12/12 with the updated streaming spec.

Not covered: `i18n-src` en-US has 1,137 keys against 1,143 elsewhere (six
`hotspot-metadata` files only the other locales have); the builder warns on it.
Same on main; not changed here.
