## How this operator works (read before acting)

- Commit locally; push only on the operator's word; never push to main from an arc.
- Before a push: `npm run preflight:coverage` once, plus the full e2e on desktop-chromium AND
  mobile-chromium (`--workers=1`, through the `long-job` skill + Monitor). Coverage thresholds
  are a ratchet: add tests, never lower them.
- Visual baselines: a change to a watched element (e.g. the /missions filter row) needs the Linux
  baselines regenerated with `scripts/regenerate-visual-baselines-linux.sh` (docker) and checked
  by eye — local runs do not compare them; CI's mobile-landscape project caught one in 0.9.7.
- All user-facing text in 14 locales; glossary `scripts/i18n-tools/native-terms.json`; names
  rule: original script only in the origin locale.
- No new scripts without approval; prefer the existing tools (READMEs per folder). No `node -e` /
  `python3 -c` / heredocs into an interpreter: write script files.
- Never put the operator's email anywhere; User-Agent contact = https://github.com/chipi/orrery.
  `scripts/_archive` is archived: don't touch or reference it.
- No GitHub issues without approval; no paid runs without a sized estimate and a go.
- Subagents: haiku proved unreliable for review / verification work in 0.9.7 (stopped early,
  counted "not found" as fixed); use sonnet for those, with a required per-file count.
