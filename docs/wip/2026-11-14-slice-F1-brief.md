## 4. Proposal
### 4.1 One length rule for the three long pages (Decision 24, 25)
A shared pure helper `previewList(list, expanded, n = 10)` in `src/lib/preview-list.ts` (unit tested) and the existing `Chip kind="action"` "Show all N", used by credits (each source's photo list and text list, audio, video, insignia) and colophon (replacing the page-local `shown`); the constant `PREVIEW = 10` moves to the helper. The source and section headers stay open. TOC anchors (`#src-<id>`, `#sec-<id>`) land on an open header with 10 rows below it, so no hash handler is needed. The "Show all" state is runtime-only (no storage). The contents lists are long too (credits 42 rows, 1,578 px at 390; library 88 rows, 2,990 px; §3): with the same helper they show 10 rows and "Show all N" on phones, and stay whole at 1024 px and up where they sit in two columns; that is part of Decision 24a, not a second rule. The 69 video posters become `loading="lazy"`; `content-visibility: auto` on `.source-block` stays.
### 4.2 Colophon totals (Decision 27)
Under the lead: `colophon_totals` "{works} original works in {sections} sections", the numbers computed once from the sections the page draws (the same array that builds the contents list), so the contents row and the heading read one value. The contents row for "Interface graphics" and "Tour episodes" use the same source as their headings.
### 4.3 Cutaways split (Decision 26)
`build-original-work.mjs` adds `kind: 'launcher' | 'spacecraft'` to each `anatomy_art` entry (the 40 launcher ids come from the fleet data's rocket category, not from image shape; the portrait measure here is the check, not the rule). The page draws "Spacecraft cutaways" (158) and "Launcher sketches" (40) with their own contents rows, counts and show-all keys; the lightbox and the overlay keys do not change. The exploded section keeps 76 with its launcher stages and landers together.
### 4.4 CR3 guard (Decision 28)
A vitest `credits-coverage.test.ts` that reads `image-provenance.json` and fails when a file under the Moon, Mars and Earth folders has no row (the folder list in §0.5), plus a one-time network audit script run on the dev server (read-only, one browser): load `/moon`, `/mars`, `/earth`, select the first three sites each, collect image requests, compare to the manifest; the result goes into the slice report, the script stays in `scripts/` with a README row (AGENTS.md "document tools as you build").
