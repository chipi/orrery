## How this repo is worked (what 0.9.9 learned)

- **Dev server**: one shared server per checkout, started detached so tool timeouts don't kill it:
  `~/.claude/skills/long-job/scripts/long-job.sh start orrery-dev --cwd <checkout> -- env
  NODE_OPTIONS=--max-old-space-size=12288 npx vite dev --port 5180 --strictPort` (it ran out of memory
  at the default heap). Pages hydrate ~3 s late on dev; specs use `waitForHydration`. Stop every dev and
  preview server in a checkout before a build there (memory `stale-preview-after-rebuild`).
- **Browser jobs one at a time** (memory `one-shared-dev-server`): use a flock wrapper (Appendix B).
- **Commits while agents share a checkout**: commit through a private index so another agent's staging
  is never swept in (Appendix A). Trailers exactly:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and your own `Claude-Session:` line.
  Subagents always get an explicit `model` (sonnet for implementers / reviewers, haiku for mechanical).
- **Pre-push**: the husky hook runs the smart preflight (full: typecheck, lint, 9.3k unit tests,
  validate-data, the build with its gates). ~20 min. Run pushes detached (long-job) and watch the log.
  Don't leave tool output inside the repo: a `test-results-*` folder failed `prettier --check .`.
- **CI**: watch with `python3 ~/.claude/skills/ci-watch/scripts/ci_watch.py <sha> --repo chipi/orrery
  --timeout-min 58` (re-arm on exit 3). `gh` refuses logs with escape codes; fetch a job log with
  `curl -sL -H "Authorization: Bearer $(gh auth token)"
  https://api.github.com/repos/chipi/orrery/actions/jobs/<id>/logs | sed -E 's/\x1b\[[0-9;]*m//g'`.
  A shard's final failures are its numbered summary list; tests that failed once then passed are flaky,
  not failures.
- **The docker-e2e runners are much slower** than the workstation (2 cores, no GPU). Reproduce CI-only
  failures in the same image locally, against a production build in the checkout:
  `docker run --rm --ipc=host --user "$(id -u):$(id -g)" -v <checkout>:/repo -v
  <linux-node-modules>:/repo/node_modules -w /repo -e CI=true -e HOME=/tmp
  mcr.microsoft.com/playwright:v1.64.0-noble npx playwright test --workers=1 --retries=0 <specs>
  --output=/tmp/...` (Linux node_modules: `scripts/regenerate-visual-baselines-linux.sh` installs them
  into `.linux-node-modules/`). A spec that only times out on CI: if the slow work *is* the test, raise

## Appendix A: commit through a private index

Put this in your scratchpad (set `R` to the checkout, `IDX` to a scratch path). Usage: `git add --
<paths>`, then `node commit-private-index.mjs <message-file> <paths>`, then `git restore --staged --
<paths>`.

```js
import { execFileSync } from 'node:child_process';
import { existsSync } from 'node:fs';
const R = '/work/orrery/worktrees/<checkout>';
const IDX = '<scratchpad>/private.index';
const [msgFile, ...paths] = process.argv.slice(2);
const git = (args, env = {}) =>
  execFileSync('git', args, { cwd: R, encoding: 'utf8', env: { ...process.env, ...env } }).trim();
const priv = { GIT_INDEX_FILE: IDX };
git(['read-tree', 'HEAD'], priv);
for (const p of paths) {
  const line = git(['ls-files', '-s', '--', p]);
  if (!line) {
    // A path staged as deleted has no entry in the shared index: commit it as a removal,
    // but only when it is really gone from the working tree too (else you forgot `git add`).
    if (existsSync(`${R}/${p}`)) throw new Error('not in shared index: ' + p);
    git(['update-index', '--force-remove', '--', p], priv);
    continue;
  }
  const [mode, blob] = line.split(/\s+/);
  git(['update-index', '--add', '--cacheinfo', `${mode},${blob},${p}`], priv);
}
const tree = git(['write-tree'], priv);
const parent = git(['rev-parse', 'HEAD']);
const commit = git(['commit-tree', tree, '-p', parent, '-F', msgFile]);
// moves HEAD only if it is still `parent` (another commit in between makes this fail)
git(['update-ref', 'HEAD', commit, parent]);
console.log(git(['show', '--stat', '--format=%h %s', commit]));
```

## Appendix B: one browser job at a time

```bash
#!/usr/bin/env bash
# bash browser-run.sh <command …>   (BROWSER_LOCK_WAIT seconds, default 3600; exit 75 on timeout)
LOCK=<scratchpad>/browser.lock
exec 9>"$LOCK"
flock -w "${BROWSER_LOCK_WAIT:-3600}" 9 || { echo "browser-run: lock not free"; exit 75; }
"$@"
```
