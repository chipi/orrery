## E. Tooling and CI (do E1–E4 early in A: the 0.9.9 release lost hours waiting on CI)

0.9.9's release: every push paid ~20 min of pre-push preflight plus ~50–60 min of CI, each change ran
the browser suite twice (branch push, then main after the merge), and desktop docker-e2e shards took
~44 min even at 6 shards. The operator asked for it to be faster (2026-11-16).

| # | Item | Notes |
|---|---|---|
| E1 | Two Playwright workers per docker-e2e shard | `--workers=1` dates from the vite-preview server crashing under parallel load; CI now serves the build with nginx in Docker. Try `--workers=2` on one run, compare times and flakes |
| E2 | The browser suite runs once per change, not twice | today: on the branch push and again on main after the squash merge; run docker-e2e on the PR (and the merge commit only as the deploy gate), not on every branch push |
| E3 | Lighter pre-push hook | the smart preflight runs the full mirror whenever config files differ from main, which is every push of a long branch; keep it for the release push, run the targeted part otherwise |
| E4 | Desktop shards 6 → 8 (or rebalance by measured time) | desktop legs ~44 min at 6 (mobile and landscape are much shorter) |
| E5 | Release gate = the full suite in the CI image locally | the docker-e2e runners are slow (2 cores, no GPU): four specs timed out there on 2026-11-16 and passed in the same image on the workstation (handover: Docker repro); review the heaviest specs' budgets |
