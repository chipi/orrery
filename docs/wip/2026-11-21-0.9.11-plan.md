## Release lessons from 0.9.10

- **CodeQL runs on the PR and is a required gate.** 0.9.10 met three alerts only after the PR opened
  (a host regex in a test without an anchor, a one-pass HTML tag strip, a no-op replace); a first fix
  cleared one, the second two. Keep tests from matching URLs by unanchored host regexes and strip
  tags to a fixpoint.
- **docker-e2e**: one worker per shard (E1, measured), shards desktop 8, mobile 6, landscape 5 (19
  jobs); runs on `pull_request`, not on branch pushes; each run about 45 min; a new push to the PR
  cancels the run in progress.
- **The merge to main** runs CI, then docker-e2e as the deploy gate (`workflow_run`). "Validate prod"
  also runs on the merge and fails on the footer version until the deploy: expected.
- **Steps after the merge**: deploy (`gh workflow run "Deploy to prod VPS (orrery)" --ref main`) →
  `validate-prod` (footer version) → `orrery-deploy-verify` with per-change proof on prod → tag the
  deployed commit and the GitHub Release from the CHANGELOG section → close the triage issues with
  the evidence. Each outward step needs the operator's go.
