## Pre-tag gate — MANDATORY (do NOT skip)

Preflight ≠ release-ready (learned on the v0.6.0→0.6.1 four-round CI ping-pong).
Before tagging, run the **full Playwright suite locally on BOTH projects**:

```bash
unset NODE_OPTIONS
npx playwright test --workers=1 --project=desktop-chromium
npx playwright test --workers=1 --project=mobile-chromium
```

- [ ] `npm run preflight:coverage` green (preflight + coverage gate)
- [ ] desktop-chromium e2e green
- [ ] mobile-chromium e2e green
- [ ] Native mobile build sanity (if shipping the app stores this cycle — separate track)

## Release sequence (three separate actions — see AGENTS.md)

1. Finalize the `## [0.8.0] — <date>` header date in CHANGELOG.
2. Confirm version consistency: `package.json` = `0.8.0`; CHANGELOG header = `[0.8.0]`.
3. Commit + push `main`; **watch CI → docker-e2e → Deploy preview to green**; verify
   staging (Pages) serves `0.8.0`.
4. `git tag v0.8.0 && git push origin v0.8.0` → `release.yml` auto-publishes the GitHub
   Release from the CHANGELOG `## [0.8.0]` section. Verify the Release entry exists.
5. Prod deploy (manual): `gh workflow run "Deploy to prod VPS (orrery)" --ref main` →
   `Validate prod` auto-fires off it (workflow_run) → verify prod serves `0.8.0`.

## Rollback

Prod deploy is idempotent + reversible (redeploy prior commit). A bad tag can be
retagged (release.yml is idempotent on re-tag). Nothing here touches shared infra.
